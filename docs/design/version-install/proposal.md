# 版本下载安装 · 提案

## 背景

「切换版本」（GUI 工具栏 / CLI 菜单 `4)`）目前只在**本机已安装的** GitHub Desktop 之间切换——Windows 上官方升级后旧的 `app-<版本>` 目录会留着，所以本机常常并存多个（本机实测 `app-3.6.4` / `app-3.6.5` / `app-3.6.6` 三个）。

但使用者的真实场景常常是「我想用某个版本，本机却没装」：升级到新版后发现汉化还没跟上、想退回旧版，或想把某个版本单独装出来做对照。此时工具只能让人自己去找安装包，而官方下载页只提供最新版，历史版本要自己去 GitHub Releases 翻。

官方为每个历史版本都发布了产物，且仓库里 `scripts/dict/release-assets.js` **已经在访问它**（为字典产出取官方的 `resources/app`）。把这份能力从「只取几个文件」扩展成「下载并铺开一个完整版本」，就能补上这条路径。

## 目标

- 「切换版本」窗口里，本机没装的版本也能选中——通过下载官方产物装出来，装完即可汉化。
- 下载在国内环境可用（走系统代理 / 环境变量代理）。
- 下载内容可校验（官方 checksums），装出来的目录与官方安装同形。

## 范围

- **做**：
  - 「可下载版本」列表：来自官方 Release，默认只列**本工具有字典的版本**（沿用窗口里已有的「显示没汉化的版本」勾选可展开全部）。
  - 下载官方产物 → 校验 sha256 → 解压到 `<安装根>/app-<版本>/`，与官方安装目录同形。
  - 下载进度：GUI 走进度条与阶段文字，CLI 打百分比。
  - **代理支持**：`net.js` 读系统代理（Windows 注册表 / macOS `scutil`）与环境变量，失败回退直连。
  - GUI 与 CLI 两个形态同步（仓库既有惯例）。
- **不做**：
  - **不运行官方 Setup.exe**：它走 Squirrel 升级语义、会替换掉现有版本，与「多版本并存 + 随时切换」的模型冲突；解压方案已实测同形（见 `design.md` 的核证表）。
  - **不做断点续传**：下载失败即重来（官方资产支持 Range，留作后续优化）。
  - **不支持 Linux**：官方不发 Linux 产物（近 30 个 release 的资产清单里一个都没有），选择时给可读提示。
  - **不做 beta 的默认展示**：beta 多数没有字典，需要时用「显示没汉化的版本」展开。
  - **不实测 macOS**：本机为 Windows；代码按平台分支写，但不声称已验证。

## 验收标准

1. 打开「切换版本」窗口：本机已装的列在「本机已安装」，本机未装但**有字典**的列在「可下载」，每项显示版本号、体积与所在目录（或「需下载」）。
2. 选中一个未装版本 → 确认框写明体积与目标目录 → 下载带进度 → 完成后自动切到该版本：状态栏显示新版本、字典表格显示该版本文典。
3. 装出来的目录与官方安装同形：`<安装根>/app-<版本>/resources/app/{main.js,renderer.js,package.json}` 存在，`common.locateApp()` 能识别，且应用可启动。
4. 校验和不符的包被拒绝，**不落盘**到安装目录（临时文件清理）。
5. 代理：设了 `HTTPS_PROXY` 或系统代理时走代理；代理不可用时**回退直连**而不是报错。
6. 已存在的版本不重复下载（列表里标为已安装）。
