# 收录判定：这条英文能不能译

字典的匹配是**逐字面量整串相等**替换。因此判定问题只有一个：**这个字面量除了被显示，还有没有别的身份？**
只要它在某处参与**比较、查表、拼接成标识符、与外部系统对齐**，翻译它就可能让那条逻辑失效。

## 零步：产物里到底有没有这个字面量？

「这个字面量除了被显示，还有没有别的身份」有个前提——**产物里确实存在这个字符串**。由**运行时生成**的文案不满足这个前提，四步检查对它无从下手：**Electron 按 `role` 生成的菜单标签**即一例（文本输入框右键菜单的 `Undo` / `Cut` / `Copy` / `Select All` / `Delete`）——官方 main.js 里 `Delete` 字面量 **0 处**，字典按字面量整串匹配，产物里没有的就无从命中。别把它记成「漏译」，也别在产物里反复找（找不到）。

> 处置：**注入代码先把英文原文造进产物**，再由同一次字典替换译掉——唯一实现是 `scripts/inject/context-menu.js`（属工具链改动，超出本技能「只改字典」的边界，见 AGENTS.md 架构一节）。注入块里的 role 名不得写成字面量（一旦字典收了 `copy` / `delete` 这样的键，角色表会被译掉、查表静默落空），故整体塞进一个字符串再 `JSON.parse`。

## 四步检查（逐条过，任何一步命中都要停下来看）

### 1. 出现位置是不是「只用于显示」？

打印该字面量的**全部**出现位置（探针 `MODE='dry'` 的位置输出），看上下文：

- **只用于显示** → 出现形态是 JSX 文本，或属性值 `label` / `title` / `ariaLabel` / `placeholder` / `okButtonText` / `okButtonTitle` / `description` / `pathPlaceholder` / `screenReaderStateMessage` / `nameFieldLabel` 等 → **可译**。
- **出现在代码表达式里**（`===` / `!==` / `indexOf(` / `case ` / `.get(` / `.set(` / `.getItem(` / `.setItem(` / `startsWith(` / `includes(` / `.push(` / 正则字面量 / 对象键）→ 继续第 2 步。

> 注意：属性白名单不能只看「名字像不像文案」——`text` / `message` / `info` / `content` / `body` / `detail` 同时是代码常用属性名。**黑名单（结构化属性名）比白名单可靠**。

### 2. 有比较/查表时，两侧是否「同源」？

- **同源**：赋值处与比较处用的是**同一批字面量**（整组会一起被同一批键替换）→ **可译**，逻辑自洽。
  实证：`"Other"` 既是分组名兜底、又被 `"Other"===e` 比较、还用于显示——三处同一来源，整组一起变中文，比较仍然成立。
- **同源但没有外层模板可覆盖**（显示与逻辑复用同一字面量，且不是运行时拼接的 JSX）：满足「整体替换」条件（见下节）时**整组同值同改**也可译——比较两侧一起变，逻辑仍自洽。
- **不同源**：比的是**运行时数据**（用户输入、API 返回值、git 输出、文件系统读取）→ **不可译**。
  实证：`n.title===t.title` 里的 `title` 来自 `git` 的进度输出，我方 `steps` 数组的 `title` 只是「用来匹配的钥匙」，显示的是 git 原文——翻译钥匙就再也对不上。

### 3. 会不会被拼接成标识符 / 查表键？

形态：`e[t+"Error"]`、`"is"+X+"Enabled"`、`n[e+"Done"]`、`classNames` 查表。

- 拼接**同源**（赋值与查找都用同一个常量表）→ 可译但要**整组一致**：只译一半（如把 `"Unknown"` / `"Abort"` 译了、`"Error"` 没译）就会查表失败。
- 拼接**不同源**（外部值 + 我方后缀）→ **不可译**；若只有某一个文件里有这种用法 → 改用**作用域键**。

### 4. 是否与外部系统对齐？

- git 的进度/错误输出匹配串（`remote: Compressing objects`、正则里的 `" because"` / `" does not"`）；
- HTTP 头名与协议常量（`Link`）；
- 环境变量名（`Path`：`Object.keys(t).find(e=>"PATH"===e.toUpperCase())||"Path"`）；
- 库内部标识符（winston 的 `"is"+X+"Enabled"`、Dexie 的错误名表、`Object.prototype.toString` 的 `"Arguments"`）；
- CSS 属性值（`style:{mixBlendMode:"difference"}`）；
- **CSS 类名（`className:"description"`）**——译掉后 `renderer.css` 里的对应规则不再命中，布局 / 间距样式静默失效，用户可见且极难排查（实测 `"description"` 21 处类名，历史列表条目「头像 + 作者・时间」那一行直接打回无 flex 布局）。

→ 一律**不可译**。

## 整体替换：显示与逻辑复用同一字面量时的出口

「显示与逻辑复用同一字面量」且**无外层模板可覆盖**时，默认保持英文（四步检查的结论）；但当**用户明确要求界面无英文**、且满足以下**全部**条件时，可整体替换（整组同值同改）：

1. **全部出现位置在同一文件**（另一文件 0 处，无跨进程 IPC / 持久化 / 上报用途——不落盘、不进 git、不发给远端）；
2. **参与比较的两侧同源**：比较 / 查表用的是同一批字面量，整组一起变后比较仍成立；
3. **配套的插值模板收尾正确**：`Begin ${…}` / `Confirm abort ${…}` 等外层模板拼出来的成句通顺。

实证（3.6.6，提交 1a150ee）：`"Rebase"` 是 `MultiCommitOperationKind` 的 const enum 值，同时是合并对话框选项的 `label` / `id` 与内部操作状态（`===` 比较、`switch case`、props/state、dispatcher 实参）——renderer.js 34 处、main.js 0 处，不落盘不进 git 不上报；34 处同值同改「变基」后 `checkedOption` 等比较两侧仍同源，配套模板收尾正确（`Begin ${…}` → 「开始 变基」）。`Squash` / `Merge` / `Cherry-pick` / `Reorder` 同为该枚举成员，结构一致时同判。

## 可译的典型形态（放心收录）

- 字符串枚举成员 / 数字枚举反向映射的值（`e.New="New"`、`e[e.Deleted=3]="已删除"`）——这类值不参与对外的比较；
  **例外**：同一枚举被别处用作工单关键词 / 拖拽取值时（如 `"Commit"` 兼作 Markdown 议题关闭关键词）→ 不可译。
- 对象字面量里的 `label` / `title` / `message` / `aria-label` 等纯展示属性。
- 模板字面量的**文本段**（`\`Fetch ${t}\`` 收录键 `"Fetch "`——含尾随空格）。
- 兜底常量：赋值处与比较处同源时（`let x = foo?.name || "Other"` … `"Other"===x`）。

## 拿不准时

1. 在**产物**里数该字面量的全部出现位置，逐处定性（这是唯一可靠的方法，别靠「这段文字像不像界面文案」）；**小写单 token 键（`description` / `archived` / `difference` / `formatting` / `Abort` 一类）先按机器标识怀疑**——早期按「形态」收词的批次会把这类 token 当文案收进来，命中全是标识就删键（同步删 groups 引用）；普查可用「字典键 × `renderer.css` 类名对撞」一次性找出类名隐患；
2. 判定不了的，**不收录**，写进汇报的「存疑待确认」清单——字典里一条错译的代价远大于一条漏译；
3. 已收录但怀疑破坏功能的：先 `npm run restore` → 启动应用对照官方原版行为 → 再决定删键还是改作用域/整模板键。
