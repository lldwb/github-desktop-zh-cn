# 版本升级：为新版本更新汉化包

GitHub Desktop 自动更新后，新的 `app-<新版本>/` 目录里是**官方原版**（汉化被覆盖）。字典与版本强对应（`patch` 版本不一致直接拒绝），因此升级后必须**为新版本新建字典**、再重新打补丁。

## 1. 定位新版本并备份

```bash
npm run locate          # 打印安装版本 / 资源目录 / 三个文件字节数，并备份到 tmp/backup/<新版本>/
```

`locate` 的备份是**已存在则跳过**——"已存在的污染备份"会静默通过，所以**先核验备份确为官方原版**：

```bash
node -e "const fs=require('fs');for(const f of ['main.js','renderer.js']){const s=fs.readFileSync('tmp/backup/<新版本>/'+f,'utf8');console.log(f,(s.match(/[一-鿿]/g)||[]).length)}"
```

**官方原版两个文件的 CJK 字符数为 0**（3.6.5 实测：备份 0 / 0，汉化产物 599 / 15706）。非 0 说明备份的已是汉化版 → 删掉 `tmp/backup/<新版本>/`，重装官方版后再 `locate`（否则后面所有"以原文为准"的取证都建立在污染样本上）。

## 2. 派生新版本字典

```bash
mkdir dictionaries/<新版本>
# 用文件管理器或 node 复制（显式路径，别用通配）
node -e "require('fs').copyFileSync('dictionaries/<上一版本>/zh-CN.json','dictionaries/<新版本>/zh-CN.json')"
```

改 `_meta.version` / `_meta.updated`（`_meta.notes` 同步）。**旧版本目录保留**——用旧版的人仍需要它，字典按版本并存。

## 3. 全量干跑：找出在新版产物里失效的条目

```js
// tmp/probe-bump.cjs —— 在新版官方原文上跑整本旧字典，收集 0 命中的条目
'use strict';
const fs = require('fs');
const path = require('path');
const { loadDict, scopedEntries, applyDictInStrings, backupDir } = require('../scripts/common');

const OLD = '<上一版本>';
const NEW = '<新版本>';
const entries = loadDict(OLD);

for (const file of ['main.js', 'renderer.js']) {
  const src = fs.readFileSync(path.join(backupDir(NEW), file), 'utf8');
  const eff = scopedEntries(entries, file); // 已剥离作用域前缀
  const { total, perKey } = applyDictInStrings(src, eff);
  const miss = [...eff.keys()].filter((k) => !perKey.has(k));
  console.log(`${file}：生效键 ${eff.size}，命中 ${total} 处，0 命中 ${miss.length} 条`);
  fs.writeFileSync(`tmp/bump-miss-${file}.txt`, miss.join('\n') + '\n', 'utf8');
}
console.log('零命中清单 → tmp/bump-miss-main.js.txt / tmp/bump-miss-renderer.js.txt');
```

失效分三类，处置不同：

| 类型 | 特征 | 处置 |
| --- | --- | --- |
| **整模板键失效** | 键以反引号开头含 `${}`；新版本重新构建后**局部变量名变了**（`GE` / `xU` 之类是构建产物里的局部名） | 按第 4 步在新版原文上重建 |
| 普通键失效 | 该文案在新版里改了词 / 被删 / 已被整模板键接管 | 按新版实际文案重写键；确认功能下线则删键 |
| 作用域键失效 | 同上，且需重新确认两个文件的语义是否仍冲突 | 同上 |

## 4. 重建整模板键

先 dump 新版产物里的全部模板源码：

```js
// tmp/probe-tpl.cjs —— 打印新版 renderer.js 里所有含插值的模板（content 含两侧反引号）
'use strict';
const fs = require('fs');
const path = require('path');
const { stringLiterals, backupDir } = require('../scripts/common');
const src = fs.readFileSync(path.join(backupDir('<新版本>'), 'renderer.js'), 'utf8');
for (const l of stringLiterals(src)) if (l.template) console.log(l.content);
```

再按旧键里的**非插值锚文本**（如 `Pull `、` with rebase`）在这批模板里检索候选，比对语义后重建：

- **键** = 新版模板源码（含两侧反引号，逐字符一致）；
- **值** = 保留 `${…}` 原样、只把可译文本段换成中文的等价模板。

> 变量名会变，**插值个数也可能变**（`.join(...)` 之类被重构）——值里的 `${…}` 必须与键里的**逐个对应**，别照抄旧值。

## 5. 补译新版本新增的文案

新版本必然新增界面文案 → 走 SKILL.md「任务 B：补充翻译」的取证流程（`npm run scan` 读的是**安装目录**的 sourcemap，升级后自动读新版源码；注意新版多出的内部错误/日志文本要按收录范围剔除）。

## 6. 打包、验证、复查、提交

```bash
npm run restore     # 该版本目录首次打补丁可跳过；只要重打就必须先还原
npm run patch       # 命中数应与干跑预期一致
npm run verify      # 版本一致 + 语法通过 + 残留清零
```

落地复查（`references/probe.cjs` 的 `MODE='land'`，抽查 10~20 条）→ 提交：

```bash
git add dictionaries/<新版本>/zh-CN.json
git commit -m "feat(dictionaries): 新增 <新版本> 字典（N 条）"
```

## 注意

- **不要拿旧版本字典直接 patch 新版本**：`patch` 会因版本不一致直接拒绝（`process.exit(2)`）；改目录名绕过会让错配的整模板键把新产物改坏。
- **`npm test`（匹配器单测）与字典无关**，只有改 `scripts/` 时才需要跑。
- `docs/` 的版本对应表若已落内容，随之同步（仓库约定：版本号概念在 `dictionaries/` 目录名、`scripts/` 校验、`docs/` 对应表三处出现）。
